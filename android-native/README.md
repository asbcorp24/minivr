# MiniVR Native для Android

Нативное Android-приложение на Kotlin и OpenGL ES 2.0. **В коде нет WebView**: изображение
проецируется на GPU самостоятельно. Сервер MiniVR/PHP продолжает хранить материалы,
экскурсии и разрешения публикации; данные читаются по HTTPS из `/api/mobile.php`.

## Реализовано на текущем этапе

- каталог опубликованных панорам и экскурсий, включая стартовую сцену;
- оформление Android в стиле основного сайта MiniVR: почти чёрный фон, фирменный
  бирюзовый акцент, логотип MINI**VR**, тонкие рамки, компактные метки и полупрозрачные панели;
- обложки опубликованных материалов и сцен из того же API загружаются асинхронно,
  миниатюры ограничены по размеру и хранятся в дисковом и небольшом RAM-кэше;
- полноэкранный контрастный каталог с вкладками «Экскурсии / Панорамы», поиском,
  крупными карточками и голубой рамкой текущего материала;
- нижняя панель с четырьмя видимыми кнопками «Назад / Сцены / Далее / Меню» без
  горизонтальной прокрутки; невозможные переходы по сценам автоматически отключены;
- нативное меню настроек с крупными переключателями, явным индикатором
  «Включено / Выключено», подсветкой фокуса и сохранением позиции прокрутки;
- информационные точки, описание и аудиоточки показываются в нативных диалогах
  с тем же оформлением, что у модального окна на сайте; иконка Android также использует
  фирменный знак MiniVR;
- списки сцен и точек аудиогида подсвечивают текущую запись; кнопки hotspot
  увеличены, а в VR показаны прицел, название выбранной точки и прогресс активации;
- нативный просмотр 360°/180°/Flat, моно и стереопары SBS / Top-Bottom;
- обычный экран показывает левый кадр стереопары, режим SBS делит дисплей на два глаза;
- сенсорный обзор, масштабирование жестом и кнопками, датчик ориентации;
- переключение сцен по списку, «назад/вперёд», автоматический маршрут по таймеру (включается вручную);
- hotspots: переход в сцену, текстовая информация, изображения, визуальные маркеры;
- стереофотографии в hotspots SBS/TB открываются в отдельном нативном GPU-просмотрщике с переключением VR;
- описание текущей сцены доступно через меню «⚙ Меню»;
- в режиме SBS — активация точек удержанием взгляда;
- комментарий сцены и звук выбранной точки рассказа (с приоритетом звука точки);
- нативный музыкальный плейлист с переключением треков и уменьшением громкости во время речи;
- 3D-параллакс на GLES 2.0 по серверной карте глубины MiniVR (`0` далеко, `1` близко):
  3 итерации луча по карте, двухмерная фильтрация глубины с сохранением резких границ,
  ослабление искажений возле полюсов, нелинейность ближнего плана и настраиваемое
  автоматическое движение (`parallaxNonlinear`, `parallaxAuto`), переключатель **3D** в меню;
- эффекты **FX** на GPU: колебание воды и листвы по нарисованным PNG-маскам,
  мультимасштабные блики живой воды, отдельные потоки реки и водопада с полями
  направлений из нарисованных на сайте стрелок (`flowArrows`);
- отдельный нативный шейдер окружения: анимированные облака, мерцающие звёзды,
  световые лучи, свечение обозначенных фонарей, кольца пузырьков, пар, плавающие
  листья и вспышки грозы; туман теперь медленно меняется по высоте и плотности;
- объёмные частицы `GL_POINTS` с перспективой и движением в пространстве: дождь,
  снежинки (включая шестилучевые), листья, насекомые с крыльями, пыль, птицы,
  пузырьки и светлячки; сцена остаётся видимой при повороте камеры;
- поддержаны и нарисованные в веб-редакторе полигональные области воды/реки/водопада
  и растительности; они преобразуются в нативные маски;
- многомасштабные JPEG-тайлы для 360° mono: сначала обзорная панорама 1024×512,
  затем детальные тайлы в направлении взгляда, с ограниченным кэшем GPU/ОЗУ;
- ранее загруженные JSON и изображения сохраняются на устройстве и доступны при потере сети.

## Пока не реализовано

- оптическая коррекция Cardboard под модель гарнитуры, настоящий WebXR/6DoF;
- полная реконструкция с многослойным закрытием просветов и тенями контактов,
  полное совпадение каждого эффекта сайта (пока перенесены упрощённые GLES-варианты);
- калибровка сложных эффектов по полигонам и 3D-частицы с индивидуальной физикой;
- полная автоматизация последовательностей рассказа;
- управление библиотекой и администрирование на телефоне;
- встроенный менеджер объёма офлайн-хранилища и push-уведомления.

Режим `SBS` — **базовый стереорендерер**, без настройки линз Cardboard. Не следует
считать его готовой заменой VR SDK.
На слабых GPU при невозможности скомпилировать расширенный шейдер приложение
автоматически использует совместимый базовый рендерер без 3D-эффектов.
Дополнительные шейдеры окружения и частиц компилируются независимо: если один из них
недоступен, 360°-просмотр продолжает работать. Если шейдер частиц недоступен,
используется прежний экранный эффект осадков.

**Разница с сайтом:** WebGL/Three.js использует отдельные трёхмерные полигональные
меши, облака точек и спрайты. На Android восстановлены направления, маски,
дискретные слои глубины и формы частиц, но световые шахты и жидкость остаются
приближёнными GLES2-эффектами. Настоящего полного 6DoF или восстановления скрытых
за объектами областей нет.

## Открыть проект и собрать APK

1. Установите Android Studio, Android SDK 35 и JDK 17.
2. Откройте папку **android-native** как отдельный проект.
3. Дождитесь Gradle Sync. Для Gradle Plugin 8.9.2 нужен Gradle 8.11.1.
4. Выполните **Build → Build APK(s)**.
5. APK появится в `app/build/outputs/apk/debug/app-debug.apk`.

Для проверки сборки добавлен GitHub Actions `MiniVR Native Android`, который
публикует отладочный APK как artifact. Перед установкой на устройство требуется
успешная сборка и проверка на реальном телефоне.

## Настройки сервера

Адрес `https://vr.specdpo.ru` указан в `app/build.gradle.kts` через поле
`API_BASE`. При смене домена нужно изменить эту строку и пересобрать приложение.
Сервер должен работать через HTTPS и содержать актуальную версию `public/api/mobile.php`.

API возвращает только **опубликованные** панорамы и экскурсии, а переходы к
неопубликованным сценам исключает. Серверную SQLite на телефон копировать не нужно.
Для тайлов API отдаёт `tiles_manifest`, если файл реально существует в `public/tiles`.
На сервере для генерации тайлов должен быть включён PHP Imagick (как и у сайта).

## Как проверить

- На обычной панораме 360° граница слева/справа должна быть бесшовной.
- На 180° за пределами видимого полушария должна быть тёмная область.
- На Flat не должно быть сферических искажений.
- На SBS/TB без очков показывается левый кадр, в режиме SBS — оба.
- В опубликованной экскурсии должны работать переходы через точки и список сцен.
- При включённом GYRO поворот телефона должен менять направление взгляда.
- После просмотра материала отключите интернет: открытая ранее сцена должна загрузиться из кэша.
- Панорама с тайлами должна появиться в низком качестве раньше крупных тайлов, а при
  приближении и повороте улучшать только текущий участок, включая переход через шов 0°/360°.
- При наличии карты глубины отключение **3D** должно убрать глубинное смещение;
  **FX** должен отключить воду, частицы и атмосферу, не выключая саму панораму.
- Для воды нарисуйте на сайте отдельные области реки и водопада и укажите стрелками
  направление: Android должен показывать разное движение, включая область у шва 360°.
- При включении дождя/снега/листьев поверните телефон: частицы должны сохранять
  перспективу и не быть жёстко приклеенными к экрану. Отключение FX убирает их.
- Проверяйте туман, звёзды, световые лучи и вспышки грозы на слабом телефоне;
  если дополнительный шейдер не поддержан, панорама всё равно должна отображаться.
- Откройте «☰ Материалы»: выбранная панорама или экскурсия должна открываться
  на своей вкладке с голубой рамкой. В «⚙ Меню» переключатели должны явно показывать
  состояние и не прокручивать список к началу после нажатия.
- Проверьте, что каталог показывает обложки там, где они есть на сервере;
  прокрутка и поиск остаются плавными, пока обложки скачиваются в фоне.

## Для разработчиков

Исходники: `app/src/main/java/ru/specdpo/minivr/`.
Рендерер использует экранный фрагментный шейдер и не нуждается в библиотеке Three.js.
Проверяйте производительность и ориентацию на нескольких моделях Android: размер
текстур, частота датчиков и поддержка GLES могут различаться.
